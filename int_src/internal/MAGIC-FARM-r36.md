# Magic Farm / Auto Run r36

Ранее обработка начиналась с FPTool.On_Hit. Обычная атака перед этим вызывает jH.viU(), реализованный PlayerWeapon.viU() -> сетевой Command vVa(). R36 вызывает этот отдельный метод при смене инструмента или соответствующего Item в переиспользованной FP-модели. Подготовка выполняется после штатной проверки готовности инструмента. Локальный FPMelee.cRp и кнопка атаки не вызываются. Код ждёт минимум 50 мс после отправки подготовки перед первым сбором; сервер сохраняет свои проверки. R35 выбирал метки, но пропускал этот сетевой этап.

В World -> Resources добавлен переключатель Auto Run. Он работает независимо от Magic Farm: при включении обоих персонаж подходит к ближайшему подходящему ресурсу выбранного типа и собирает его. Нужен соответствующий топор/кирка. Search Distance ограничивает поиск. Остановка происходит вблизи ресурса, внутри Farm Distance. Направление движения преобразуется в обычный игровой ввод относительно текущего направления игрока; взгляд не поворачивается принудительно. Состояния движения и спринта передаются штатным обработчикам и структуре PlayerInput.

Джойстик приостанавливает Auto Run, меню, смерть и потеря цели прекращают движение. Проверяются короткие свободные направления и опора впереди. При застревании движение останавливается. Это локальное обходное движение, без глобального поиска пути по карте: сложная ограда или многоэтажная геометрия могут потребовать ручного прохода.

Сохранение настроек использует EXTRAS_V2. Старые EXTRAS_V1 загружаются с выключенным Auto Run. Крестики/свечение продолжают считываться перед каждым сбором, HitStreak подготавливает сама игра.

На устройстве проверить: включить Magic Farm, закрыть меню, несколько раз сменить топор/кирку и добывать без каких-либо ручных ударов; проверить новые предметы с переиспользуемой FP-моделью; включить Auto Run и проверить подход, остановку, переход к следующему ресурсу, ручной джойстик, выключение функции и открытие меню. Сборка и host-тесты не подтверждают успешную добычу на игровом сервере.
